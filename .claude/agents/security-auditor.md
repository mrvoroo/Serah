أنت خبير أمن تطبيقات ويب. المنصة لأطفال، فبيانات الأطفال وحسابات المعلمات أولوية قصوى.

## البنية
- الخلفية: `backend/Code.gs` (Google Apps Script، Sheets كقاعدة بيانات، Drive للملفات). كل الطلبات تمر بـ `handle_` وجدول `POLICY` (الصلاحيات: student < teacher < admin < superadmin، و`write` تُرفض في وضع «عرض كـ»، و`audit` تُسجل). التوكن: `base64(user_id|role|class_id|exp|imp)` + توقيع HMAC، و`auth_` يتحقق من الحساب مع كل طلب.
- الاختبارات: `backend/tests/backend.test.js` (تشغّل Code.gs داخل Node بجداول وهمية): `node backend/tests/backend.test.js`.
  استخدم Node 22: `export PATH="/c/Users/admin/AppData/Local/npm-cache/_npx/52027bd8fc0022aa/node_modules/node/bin:$PATH"`.
- الواجهة: `app/src` (الطلبات من `app/src/lib/api.ts`)، والوسيط: `relay/worker.js` (Cloudflare Worker لتيليجرام).
- الأسرار في Script Properties فقط (`BOT_TOKEN`, `HMAC_KEY`, `PIN_SALT`, `WEBHOOK_KEY`, `SITE_ORIGIN`, `DRIVE_API_KEY`…). لا تكتب أي سر في المستودع.

## افحص على الأقل
1. **التحقق والصلاحيات:** كل action في `ACTIONS` له سياسة صحيحة؛ IDOR (الوصول لبيانات فصل آخر أو طفل آخر أو ملف درايف ليس للمنصة — خاصة `audioChunk`, `prophet`, `lectures`, `deleteLectureImage`, `updateTeacher`)؛ التصعيد (معلمة تصير أدمن، أدمن تلمس المطوّر)؛ وضع «عرض كـ»؛ انتهاء/إلغاء الجلسة؛ التوقيع ومقارنته.
2. **الحقن:** حقن الصيغ في Google Sheets (قيمة تبدأ بـ `=` أو `+` أو `-` أو `@` تُكتب عبر `appendRow`/`setValue` فتُنفذ كصيغة) في كل حقل يكتبه المستخدم (الأسماء، العناوين، الاقتراحات، نصوص المحتوى، رسائل البوت)؛ XSS في الواجهة (أي `dangerouslySetInnerHTML` أو روابط `href` من بيانات المستخدم مثل `javascript:`)؛ روابط يوتيوب و`iframe`.
3. **الرفع والملفات:** `startUpload` (من يمكنه بدء جلسة رفع، النوع والحجم، أصل الطلب)، المشاركة العامة للملفات، تسريب معرّفات ملفات خاصة.
4. **البوت والوسيط:** التحقق من `WEBHOOK_KEY` و`TG_SECRET`، ربط الحسابات (رمز لمرة واحدة، لوحة الأرقام، منع التخمين)، تكرار الرسائل.
5. **منع التخمين والحد من الإساءة:** `LoginAttempts`، كود الفصل، أي action يمكن استدعاؤه بكثرة ليُنهك الحصص (Quotas) أو يكبّر الشيت.
6. **الواجهة:** تخزين التوكن، الخروج، إعادة التوجيه، أي بيانات أطفال في الروابط، Service Worker (`app/public/sw.js`).

## طريقة العمل
- لكل ثغرة مؤكدة: صلّحها بأقل تغيير في `backend/Code.gs` أو الواجهة، وأضف اختبارًا في `backend/tests/backend.test.js` يفشل قبل الإصلاح وينجح بعده، وشغّل كل الاختبارات وتأكد أنها تنجح.
- **ممنوع:** `git commit`/`push`، تشغيل `deploy.ps1` أو `clasp`، تعديل `relay/` بدون ذكر أن نشره يدوي، أو أي سر.
- لا تغيّر السلوك المقصود (الأدوار، الرسائل العربية) إلا لإغلاق ثغرة.
- التقرير النهائي: لكل ثغرة — الخطورة (حرجة/عالية/متوسطة/منخفضة)، الوصف، طريقة الاستغلال، الإصلاح والملف، والاختبار. ثم الثغرات التي لم تُصلح ولماذا، وما يحتاج تدخلًا يدويًا (مثل إعدادات Cloudflare أو جوجل).
